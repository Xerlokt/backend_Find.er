O método implementa a decisão D-06: se o email já existe (conta email/password), vincular o `googleId`. Se não existe, criar novo usuário.

```typescript
async findOrCreateGoogleUser(data: {
  googleId: string
  email: string
  name?: string
  avatarUrl?: string
  role: 'CANDIDATE' | 'RECRUITER'
}): Promise<{ user: User; isNew: boolean }> {
  // Tentar encontrar por googleId primeiro (já vinculado)
  const byGoogleId = await prisma.user.findUnique({
    where: { googleId: data.googleId },
  })
  if (byGoogleId) {
    return { user: byGoogleId, isNew: false }
  }

  // D-06: email existente → vincular googleId ao usuário existente (upsert por email)
  const existing = await prisma.user.findUnique({ where: { email: data.email } })
  if (existing) {
    const updated = await prisma.user.update({
      where: { id: existing.id },
      data: {
        googleId: data.googleId,
        avatarUrl: data.avatarUrl ?? existing.avatarUrl,
      },
    })
    return { user: updated, isNew: false }
  }

  // D-05: primeira autenticação Google → criar novo usuário
  const created = await prisma.user.create({
    data: {
      email: data.email,
      googleId: data.googleId,
      avatarUrl: data.avatarUrl,
      role: data.role as Role,
      // passwordHash: null — conta Google não tem senha local
    },
  })
  return { user: created, isNew: true }
}
```

```typescript
// No topo do arquivo, adicionar import:
import { OAuth2Client } from 'google-auth-library'

// Inicializar cliente Google fora da classe (singleton por módulo):
const googleClient = new OAuth2Client(process.env.GOOGLE_CLIENT_ID)

// Adicionar método à classe AuthService, após logout:
async loginWithGoogle(input: {
  idToken: string
  role: 'CANDIDATE' | 'RECRUITER'
}): Promise<TokenPair> {
  let googlePayload: { sub: string; email: string; name?: string; picture?: string }

  try {
    const ticket = await googleClient.verifyIdToken({
      idToken: input.idToken,
      audience: process.env.GOOGLE_CLIENT_ID,
    })
    const payload = ticket.getPayload()!
    googlePayload = {
      sub: payload.sub,
      email: payload.email!,
      name: payload.name,
      picture: payload.picture,
    }
  } catch {
    // google-auth-library lança Error genérico — não subclasse tipada (Pitfall 3)
    throw new AppError('Invalid Google token', 401, 'INVALID_CREDENTIALS')
  }

  const { user } = await this.repo.findOrCreateGoogleUser({
    googleId: googlePayload.sub,
    email: googlePayload.email,
    name: googlePayload.name,
    avatarUrl: googlePayload.picture,
    role: input.role,
  })

  const familyId = randomBytes(16).toString('hex')
  return this.generateTokenPair(user.id, user.role as string, familyId)
}
```

<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| Client → POST /auth/google | idToken vem do client Google OAuth — não confiável; validado pelo servidor Google via google-auth-library |
| google-auth-library → Google servers | Biblioteca faz requests HTTPS aos servidores Google para verificar a assinatura do token |
| AuthRepository → PostgreSQL | Upsert por email pode vincular contas — decisão D-06 aceitada como intencional |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-14 | Spoofing | POST /auth/google — idToken falsificado | mitigate | google-auth-library OAuth2Client.verifyIdToken verifica assinatura criptográfica do Google + audience + expiry (ASVS V2.2.3) |
| T-2-15 | Elevation of Privilege | POST /auth/google — role ADMIN no body | mitigate | GoogleBodySchema z.enum(['CANDIDATE', 'RECRUITER']) exclui ADMIN → Zod lança → 400 (D-09) |
| T-2-16 | Information Disclosure | google-auth-library — chave pública Google | accept | Biblioteca gerencia rotação de chaves automaticamente; não há exposição de secrets locais |
| T-2-17 | Spoofing | Account linking D-06 — vinculação por email | accept | Vinculação ocorre apenas quando o Google confirma que o email pertence ao autenticado (ticket.getPayload().email); risco aceito conforme decisão D-06 |
| T-2-18 | Tampering | GOOGLE_CLIENT_ID não setado em produção | mitigate | google-auth-library lançará erro na audience check → AppError 401 INVALID_CREDENTIALS; não há bypass possível |
| T-2-19 | Denial of Service | POST /auth/google sem rate limit específico | accept | Rate limit global de 60/min por IP aplica via @fastify/rate-limit; rota Google não é alvo primário de brute force (token é assinado externamente) |
</threat_model>
