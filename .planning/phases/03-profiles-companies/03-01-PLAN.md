<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → PUT /candidates/me | Untrusted body; userId must never come from body |
| JWT → request.user | Trusted after `authenticate` hook verifies signature; `request.user.id` is the canonical userId |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Information Disclosure (IDOR) | `PUT /candidates/me` | mitigate | `userId` always from `request.user.id` (JWT-verified); body never contains userId field; verified by `grep -n "request\.user\.id"` acceptance criterion |
| T-03-01-02 | Tampering (Mass Assignment) | `CandidateProfileSchema.parse()` | mitigate | Zod `parse()` with explicit schema strips unknown fields; `salaryExpectation` field in Zod schema is typed `z.number().positive().optional()` — negative values rejected |
| T-03-01-03 | Tampering (SQL Injection) | `CandidateRepository` | mitigate | All queries via Prisma ORM parameterized methods (`upsert`, `findUnique`) — no `$queryRaw` with user input (SEC-01) |
| T-03-01-04 | Elevation of Privilege | `PUT /candidates/me` | mitigate | `preHandler: [authenticate, requireRole('CANDIDATE')]` — RECRUITER and ADMIN receive 403 FORBIDDEN |
| T-03-01-05 | Elevation of Privilege | `GET /candidates/me` | mitigate | `preHandler: [authenticate, requireRole('CANDIDATE')]` — only CANDIDATE role can read own profile |
</threat_model>
