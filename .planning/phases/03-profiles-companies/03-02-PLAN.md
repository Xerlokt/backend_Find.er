<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /companies | Untrusted body; only ADMIN role may create companies |
| Client → PATCH /companies/admin/:id/credits | Untrusted amount; must be positive int; service guards against negative balance |
| JWT → request.user.role | Trusted after `authenticate` hook; role check enforced by `requireRole('ADMIN')` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Elevation of Privilege | `POST /companies` | mitigate | `preHandler: [authenticate, requireRole('ADMIN')]` — CANDIDATE and RECRUITER receive 403 FORBIDDEN (ADMIN-03) |
| T-03-02-02 | Elevation of Privilege | `PATCH /companies/admin/:id/credits` | mitigate | `preHandler: [authenticate, requireRole('ADMIN')]` — only ADMIN can adjust credits (ADMIN-02, ADMIN-03) |
| T-03-02-03 | Tampering (Credits Manipulation) | `AdjustCreditsSchema` | mitigate | `z.number().int().positive()` — Zod rejects zero, negative, and non-integer values before service call |
| T-03-02-04 | Tampering (Negative Balance) | `CompanyService.adjustCredits` | mitigate | Service checks `company.credits + delta < 0` before calling repository; throws 400 INSUFFICIENT_CREDITS |
| T-03-02-05 | Tampering (Race Condition on Credits) | `CompanyRepository.adjustCredits` | mitigate | Prisma `{ credits: { increment: delta } }` is atomic at DB level — never read-then-write (SEC-03) |
| T-03-02-06 | Tampering (SQL Injection) | `CompanyRepository` | mitigate | All queries via Prisma ORM parameterized methods — no `$queryRaw` with user input (SEC-01) |
| T-03-02-07 | Tampering (Mass Assignment) | `CreateCompanySchema.parse()` | mitigate | Zod parse with explicit schema strips unknown fields; `plan`, `rating`, `credits` not in schema (cannot be set by client) |
</threat_model>
