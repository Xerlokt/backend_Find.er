<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → PUT /recruiters/me | Untrusted companyId; service validates FK before upsert |
| Client → GET /admin/users | Admin-only; request.user.id from JWT; response must exclude sensitive fields |
| Client → PATCH /admin/companies/:id/credits | Admin-only; amount must be positive integer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Information Disclosure (IDOR) | `PUT /recruiters/me` | mitigate | `userId` always from `request.user.id` (JWT-verified); companyId from body is FK reference only, not userId |
| T-03-03-02 | Elevation of Privilege | `PUT /recruiters/me` | mitigate | `preHandler: [authenticate, requireRole('RECRUITER')]` — CANDIDATE and ADMIN receive 403 |
| T-03-03-03 | Tampering (Invalid FK) | `RecruiterService.upsertProfile` | mitigate | `findCompanyById` check before upsert; throws 404 if company not found; prevents Prisma P2003 FK violation surfacing as 500 |
| T-03-03-04 | Elevation of Privilege | All `/admin/*` routes | mitigate | `preHandler: [authenticate, requireRole('ADMIN')]` on every handler in adminRoutes — verified by acceptance criterion grep |
| T-03-03-05 | Information Disclosure | `GET /admin/users` | mitigate | Prisma `select` explicitly excludes `passwordHash` and `googleId` from all user responses; verified by grep on admin.service.ts |
| T-03-03-06 | Tampering (SQL Injection) | `RecruiterRepository`, `AdminService` | mitigate | All queries via Prisma ORM parameterized methods — no `$queryRaw` with user input (SEC-01) |
| T-03-03-07 | Tampering (Mass Assignment) | `RecruiterProfileSchema.parse()` | mitigate | Zod schema contains only `companyId: z.string().uuid()` — no other fields can be injected |
| T-03-03-08 | Tampering (Credits via Admin) | `AdminService.adjustCredits` | mitigate | `AdjustCreditsAdminSchema` validates `z.number().int().positive()` — zero and negative values rejected before service call |
</threat_model>
