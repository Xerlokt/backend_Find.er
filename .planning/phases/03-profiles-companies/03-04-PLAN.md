<objective>
Corrigir violação de Clean Architecture em `CompanyService.adjustCredits` que causa 2 falhas nos testes unitários.

**Causa raiz:** `CompanyService.adjustCredits` importa `prisma` diretamente e executa `$transaction` com queries raw (`tx.company.findUnique`, `tx.company.update`, `tx.creditTransaction.create`). Os testes unitários mockam `repo.findById` e `repo.adjustCredits` — que nunca são chamados. O service bate numa transação Prisma real sem banco disponível e lança `AppError: Company not found`.

**O que o teste espera:**
1. `repo.findById(companyId)` → verifica existência e lê saldo atual
2. Service checa `company.credits + delta < 0` → lança 400 INSUFFICIENT_CREDITS se negativo
3. `repo.adjustCredits(companyId, delta)` → persiste no banco

**Fix:** Mover a lógica de `$transaction` para o repositório e fazer o service usar o repo em todos os caminhos.

Output: testes unitários do `CompanyService` passando com código 0.
</objective>

  ```typescript
  async adjustCredits(companyId: string, delta: number) {
    return prisma.$transaction(async (tx) => {
      const updated = await tx.company.update({
        where: { id: companyId },
        data: { credits: { increment: delta } },
      })
      await tx.creditTransaction.create({
        data: { companyId, amount: delta, reason: 'admin_grant' },
      })
      return updated
    })
  }
  ```

  A assinatura permanece `(companyId: string, delta: number)` — sem `reason` — para corresponder ao contrato que o teste espera (`toHaveBeenCalledWith('company-1', 50)`).

  O `reason: 'admin_grant'` é fixo porque `CompanyService.adjustCredits` só é chamado pelo endpoint admin de ajuste de créditos.
