From @fastify/websocket (v11) — injectWS API:
```typescript
// Signature: app.injectWS(path, upgradeContext?, options?)
// upgradeContext.headers are merged into the upgrade request headers
// The promise resolves to a WebSocket instance after the 'open' event fires
// If server sends close BEFORE upgrade completes (auth hook 401): promise rejects with Error('Unexpected server response: 401')
// If close(1008) is sent AFTER upgrade (in handler body): promise resolves, then 'close' event fires on ws

// Usage with auth header:
const ws = await app.injectWS('/chats/CHAT_ID/ws', {
  headers: { authorization: 'Bearer TOKEN' }
})

// Awaiting message from server:
const msg = await new Promise<string>((resolve) => {
  ws.once('message', (data) => resolve(data.toString()))
})

// Awaiting close code:
const code = await new Promise<number>((resolve) => {
  ws.on('close', (code) => resolve(code))
})

// ALWAYS call ws.terminate() to avoid Jest open handle warnings
ws.terminate()
```
