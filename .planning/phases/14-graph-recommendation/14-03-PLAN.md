**Note on 0-hop handling:** CONTEXT.md D-01 and ROADMAP.md SC-4 both lock the traversal depth to `*1..2`. This means the RELATED_TO relationship pattern must NOT use `*0..2`.
```typescript
// Factor 2: Skills overlap (35%) — Neo4j RELATED_TO*1..2 traversal with hop decay (Phase 14, D-01)
// 0-hop (direct match) handled via CASE WHEN clause; *1..2 handles adjacency only (D-01 / SC-4)
const WEIGHT: Record<number, number> = { 0: 1.0, 1: 0.8, 2: 0.6 }
let skillsScore: number
if (job.requiredSkillIds.length === 0) {
  skillsScore = 1.0
} else {
  const session = this.driver.session({ defaultAccessMode: neo4j.session.READ })
  let adjacency: Array<{ skill: string; hops: number }> = []
  try {
    const result = await session.run(
      `UNWIND $requiredSkillIds AS reqId
       OPTIONAL MATCH path = (cand:Skill)-[:RELATED_TO*1..2]->(adj:Skill {id: reqId})
         WHERE cand.id IN $candidateSkillIds
       WITH reqId,
            reqId IN $candidateSkillIds AS isDirect,
            min(toInteger(length(path))) AS minPathLen
       WITH reqId,
            CASE
              WHEN isDirect THEN 0
              WHEN minPathLen IS NOT NULL THEN minPathLen
              ELSE null
            END AS hops
       WHERE hops IS NOT NULL
       RETURN reqId AS skill, hops`,
      {
        requiredSkillIds: job.requiredSkillIds,
        candidateSkillIds: candidate.skillIds,
      },
    )
    adjacency = result.records.map((r) => ({
      skill: r.get('skill') as string,
      hops: r.get('hops') as number,
    }))
  } finally {
    await session.close()
  }
  const totalWeight = adjacency.reduce((sum, { hops }) => sum + (WEIGHT[hops] ?? 0), 0)
  skillsScore = Math.min(totalWeight / job.requiredSkillIds.length, 1.0)
}
```

**Why this Cypher is correct — aggregation is required:**

The single `OPTIONAL MATCH path = (cand:Skill)-[:RELATED_TO*1..2]->(adj:Skill {id: reqId})` can produce multiple rows per `reqId` when multiple candidate skills can reach the same required skill at different depths. For example, if candidate has `['sql', 'nodejs']` and the job requires `['postgresql']`, and both `sql→postgresql` (1-hop) and `nodejs→...→postgresql` (2-hop, hypothetically) exist, the OPTIONAL MATCH produces two rows for `reqId=postgresql`. Without `min()`, the TypeScript reducer would count both weights (0.8 + 0.6 = 1.4), inflating the score. The `min(toInteger(length(path))) AS minPathLen` aggregation collapses all paths for the same `reqId` to the shortest one before the CASE WHEN branch evaluates — each `reqId` produces exactly one output row.

**Critical checks:**
- The Cypher string must contain `RELATED_TO*1..2` — NOT `RELATED_TO*` (unbounded) and NOT `RELATED_TO*0..2` (which contradicts D-01 / SC-4)
- The `min()` aggregation must be present — without it, a required skill reachable by multiple candidate skills at different depths produces duplicate rows
- Parameters must use `requiredSkillIds` and `candidateSkillIds` exactly as shown (matching the Cypher `$` parameter names)
- The session must use `neo4j.session.READ` (this is a read-only traversal)
- `WEIGHT` constant is defined inside the method body — not at class or module level (keeping it co-located with usage)
- After the replacement, `computeFitScore` is now `async` (it was already marked async in the method signature)
