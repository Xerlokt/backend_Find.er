```typescript
export function getRedisClient(): Redis {
  if (!redisClient) {
    const url = process.env.REDIS_URL ?? 'redis://localhost:6379'
    redisClient = new Redis(url)
  }
  return redisClient
}
export async function closeRedis(): Promise<void> {
  if (redisClient) { await redisClient.quit(); redisClient = null }
}
```
CRITICAL: process.env.REDIS_URL must be overridden BEFORE any module imports getRedisClient() — because the singleton initializes lazily, the override must happen at the top of setup.ts (before any import that triggers module evaluation).

Note on `process.env.REDIS_URL` placement: In Jest, `import` statements are hoisted at compile time but module execution happens at runtime. The `process.env.REDIS_URL = ...` assignment at the top of the file (before the import block) executes before any module is evaluated in CommonJS (ts-jest compiles to CJS). This ensures the Redis singleton picks up the test URL.

If the `redis_test` Docker service is not running when tests execute, the Redis client will fail to connect — but the try/catch in use cases will silently fall through to source-of-truth. Integration tests that assert cache behavior DO require `redis_test` to be running.
